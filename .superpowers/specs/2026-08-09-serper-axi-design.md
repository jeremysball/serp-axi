# serper-axi design

Date: 2026-08-09
Revision: 2 (rewritten after a ferried plan review; see "Revision history")

## Purpose

An AXI-compliant CLI that lets agents run Serper (Google Search API) queries
and page scrapes via shell execution, with token-efficient TOON output,
structured errors, and no interactive prompts.

## Architecture

Standalone TypeScript package, npm-private (not published), living at the
root of its own repo. No absolute path is baked into any file; the package
is located by whatever directory it is cloned into.

```
serper-axi/
  src/
    serper.ts          <- HTTPS client for the two Serper endpoints
    commands/
      search.ts
      scrape.ts
      update.ts
    bin/
      serper-axi.ts     <- runAxiCli() entrypoint
  .mise.toml            <- pinned Node runtime
  package.json
  SKILL.md              <- hand-written; discovery path for agents
```

- `src/bin/serper-axi.ts` wires everything through `axi-sdk-js`'s
  `runAxiCli()`, which supplies command-first dispatch, bare
  `--help`/`--version`, TOON serialization, and structured `AxiError`
  handling.
- `src/serper.ts` calls Serper's HTTPS API directly with the runtime's
  global `fetch`. No MCP layer, no subprocess, no code generation.
- Sole runtime dependency: `axi-sdk-js`, pinned to an exact version. Node
  is pinned in `.mise.toml`.
- Install: `npm run build && npm install -g .`, which places `serper-axi`
  on `PATH` via whatever prefix npm is configured with.

### Why not MCP / mcporter

The first revision of this spec routed through `mcp-server-serper` via a
CLI generated by `mcporter generate-cli`. That was abandoned after the
review established, by running the tool, that:

- the generated artifact has zero `export` statements and auto-runs its own
  CLI at import time, so it cannot be imported as a client;
- it imports `mcporter` and `commander` at runtime under a
  `#!/usr/bin/env bun` shebang, so mcporter could not have been a
  generation-time-only dependency as claimed;
- it embeds the absolute path of its generation directory into the emitted
  file.

With the "generate once, own the client, no runtime dependency" property
disproved, the remaining MCP stack was a spawned `npx` subprocess and a
stdio protocol wrapping two HTTPS POSTs, plus a runtime dependency on the
npm registry being reachable. Calling the API directly removes the
subprocess, the protocol, the unpinned `npx -y` fetch, and the generated
file — and returns real HTTP status codes, which is what the error design
below needs. mcporter remains useful at the terminal for inspecting MCP
servers; it is not part of this product.

## Serper API surface

Verified against the live API on 2026-08-09. Both endpoints authenticate
with an `X-API-KEY` header and take a JSON body.

**Search** — `POST https://google.serper.dev/search`

- Request: `{ q, gl, hl, num }`
- Response: `{ searchParameters, organic[], peopleAlsoAsk?,
  relatedSearches?, credits }`
- `organic[i]` carries exactly `position`, `title`, `link`, `snippet`.
- The response contains **no total-result count**. Output therefore reports
  only how many results came back, and never states a total it cannot know.
- `answerBox` was not present in any probe response and is not specified
  here. v1 ignores it rather than guessing a shape.

**Scrape** — `POST https://scrape.serper.dev`

- Request: `{ url }`
- Response: `{ text, metadata, credits }`, where the page title is
  `metadata.title`.

**Errors** — both endpoints return a matching HTTP status with a JSON body
of `{ message, statusCode }`. Verified: a bad key returns **403** with
`{"message":"Unauthorized.","statusCode":403}` (403, not 401), and an
unreachable page returns 404 with `{"message":"Page not found.",...}`.

## Commands

### `serper-axi search "<query>" [--region <cc>] [--lang <code>] [--num <n>]`

Flag mapping to the API, stated explicitly so no handler has to guess:
`--region` → `gl`, `--lang` → `hl`, `--num` → `num`.

- Defaults: `--region us`, `--lang en`, `--num 10`.
- Validation, before any network call, exit code 2 on failure: `--num` is an
  integer in 1..100 (serper-axi's own clamp); `--region` and `--lang` are
  non-empty lowercase ASCII.
- Output (TOON): `count` (results returned), then `results` with schema
  `position,title,link,snippet`, snippet truncated to 200 characters.
  Snippet stays in the default schema — without it an agent cannot judge
  relevance without a follow-up scrape.
- `--fields <a,b,c>` adds fields beyond the default schema, per AXI's
  minimal-default-schema rule. v1 accepts `date` and `sitelinks`, which
  `organic[i]` carries on some results; an unknown field name is a usage
  error listing the accepted set.
- Zero results: `results: 0 results found for query "<query>"`, exit 0.
- Contextual disclosure: suggest `serper-axi scrape "<link>"` using a
  placeholder, not a guessed concrete URL.

### `serper-axi scrape <url> [--full]`

- Validation, before any network call, exit code 2 on failure: scheme must
  be `http` or `https` (rejects `file:`, `data:`, and the rest); host must
  not be a loopback or private-range literal.
- Output (TOON): `url`, `title` (from `metadata.title`; omitted entirely
  when the API returns none — no invented value), `text` truncated to 1200
  characters with the total character count noted.
- `--full` returns untruncated text up to a hard 50,000-character ceiling,
  and says so explicitly when the ceiling is hit. Unbounded output would
  exhaust the calling agent's context.
- The `--full` hint appears only when content was actually truncated.

### `serper-axi update`

Registered explicitly, which prevents `axi-sdk-js`'s reserved built-in
`update` from taking the name. The built-in resolves the package against
the npm registry and errors `not published to the npm registry` for a
private package, so shipping it would mean an advertised command that can
only fail. Ours instead reports that this is a local install and prints the
upgrade path (`git pull && npm run build && npm install -g .`), exit 0.

### No-args home view

A stateless action tool has no list of things to show ambiently. The home
view shows `bin` (path, `~`-collapsed), a one-line description, and both
commands as usage examples with placeholder arguments.

## Errors

Every failure surfaces on stdout as a structured `error:`/`help:` pair via
`AxiError` — never a stack trace, raw body, or dependency name. Because the
API returns `{ message, statusCode }` uniformly, translation is a single
mapping rather than per-call guesswork:

| Condition | Behavior |
|---|---|
| `SERPER_API_KEY` unset or empty | Checked before any network call. `error: SERPER_API_KEY is not set` / `help: export SERPER_API_KEY=<your key> and re-run` |
| 403 | Key rejected — help names the env var to check |
| 429 | Rate limited — help says to retry later |
| 404 (scrape) | Page not found — help suggests verifying the URL |
| 5xx | Upstream failure — help says to retry |
| Any other status, non-JSON body, or network error | Reported explicitly as an unknown failure including the observed HTTP status and a bounded excerpt of the body. Never collapsed into a generic success-shaped or silently-swallowed result. |

Unknown flags and unknown positional arguments are rejected by name with
exit code 2, listing that subcommand's valid flags inline.

Exit codes: 0 success (including a zero-result search and a no-op
`update`), 1 error, 2 usage error.

## AXI compliance

The tool is built against the ten AXI rules, and each is satisfied
somewhere above. Restated here so nothing is left implicit, and so the two
deliberate deviations are visible rather than accidental:

1. **Token-efficient output** — TOON on stdout, converted at the output
   boundary; internal logic stays on plain objects. The TOON spec is
   required reading before the first line of output code is written.
2. **Minimal default schemas** — 4 fields on search results, with
   `--fields` as the explicit escape hatch.
3. **Content truncation** — snippets at 200 characters, scrape text at
   1200, both reporting the full size, with `--full` offered only when
   content was actually cut.
4. **Pre-computed aggregates** — `count` is emitted on every search. A
   total-matches figure is *not*, because the API does not return one;
   stating a total we cannot know would be a fabricated aggregate, which is
   worse than an absent one.
5. **Definitive empty states** — a zero-result search says so in words and
   exits 0.
6. **Structured errors, channels, exit codes** — errors are TOON
   `error:`/`help:` pairs on **stdout**; **stderr** carries only diagnostics
   and progress, never data. No command ever prompts: every operation
   completes from flags alone, and a missing required value fails
   immediately instead of asking. Unknown flags and arguments are rejected
   by name with exit 2 before any network call, listing that subcommand's
   valid flags inline so the agent self-corrects in one turn.
7. **Session integration** — a hand-written `SKILL.md` ships as the
   discovery path, with trigger-shaped frontmatter and command examples
   that work for a local install (this package is not on npm, so an
   `npx -y serper-axi ...` example would be a lie). The SessionStart hook is
   deliberately skipped; see out of scope.
8. **Content first** — *deliberate deviation.* A stateless search tool has
   no live state to show, so the no-args view gives identity plus runnable
   examples. There is no manufactured "state" and no full usage manual.
9. **Contextual disclosure** — a search suggests scraping a result; an
   empty search suggests a different query; every error's help line names
   the exact command or variable that fixes it. The scrape detail view is
   self-contained and carries no suggestions.
10. **Consistent help** — the home view leads with `bin` (absolute path,
    home collapsed to `~`) and a one-line description. Every subcommand
    supports `--help` with its own flags, defaults, required arguments, and
    2-3 examples, scoped to that subcommand rather than dumping the whole
    CLI.

## Testing

- Unit tests cover flag validation, the error mapping table, truncation
  boundaries, and TOON output shape, with the HTTP layer faked.
- Because a fully-mocked suite proves nothing about the real boundary, one
  test exercises the live API against `SERPER_API_KEY` for both endpoints
  and is skipped with an explicit message when the key is absent.

## Explicitly out of scope for v1

- **SessionStart hook / ambient session integration.** Nothing stateful
  exists to surface at session start, so a hook would cost tokens on every
  session with no payoff.
- **Publishing to the npm registry.** Stays a local, globally-installed
  package.
- **`answerBox`, `peopleAlsoAsk`, and `relatedSearches` passthrough.** The
  API returns the latter two; v1 does not emit them, to keep the default
  output minimal. Revisit if an agent actually needs them.

`SKILL.md` ships in v1 as a hand-written file. The first revision proposed
generating it from the home view with a `--check` drift step; that is a
generator and a CI gate guarding two short static texts, so it is dropped
in favor of writing the file once.
